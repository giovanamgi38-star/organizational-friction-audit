# Organizational Friction Audit

**A no-code, practical toolkit for identifying organizational bottlenecks and turning them into actionable improvements.**

**Kit práctico, sin código, para identificar fricciones organizacionales y convertirlas en mejoras concretas.**

> **Status / Estado:** Public prototype / Prototipo público. This is a demonstration framework, not a validated psychometric instrument. / Es una herramienta de demostración, no un instrumento psicométrico validado.

## The problem / El problema

Organizations often experience delays, duplicated work, unclear ownership, unnecessary approvals, and information scattered across teams. These problems are frequently mistaken for individual productivity issues.

En muchas organizaciones se repiten retrasos, trabajo duplicado, roles poco claros, autorizaciones excesivas e información dispersa. A menudo se confunden problemas de diseño organizacional con problemas de productividad individual.

## How to use / Cómo usarlo

1. Conversa con personas de diferentes funciones utilizando la plantilla.
2. Registra hechos observables, no únicamente opiniones.
3. Identifica patrones repetidos y valida los hallazgos con el equipo.
4. Prioriza problemas utilizando la matriz.
5. Define cambios pequeños, responsables e indicadores de seguimiento.

## Example outcomes / Resultados posibles

- Clarify who decides and who contributes to each decision.
- Reduce unnecessary approvals and handoffs.
- Make blockers visible before they become emergencies.
- Standardize recurring tasks while keeping human oversight.

## Intended audience / A quién está dirigido

NGOs, social-impact organizations, growing teams, and managers reviewing organizational ways of working.

ONG, organizaciones de impacto, equipos en crecimiento y responsables de mejorar procesos internos.

## Responsible use / Uso responsable

- No publiques nombres, datos personales, información de donantes o diagnósticos reales de clientes sin autorización explícita.
- Evita usar puntuaciones para evaluar el desempeño individual; el objetivo es mejorar sistemas, no señalar personas.
- La herramienta necesita adaptación al contexto y validación con quienes hacen el trabajo.
- Todos los ejemplos aquí son **ficticios**.
